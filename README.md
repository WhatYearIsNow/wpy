# 微北洋「青年湖底」论坛工具集

针对天津大学微北洋 App 的「青年湖底」（求实论坛）的**全站抓取 + 本地看板**。

> 数据来源为微北洋官方接口，与 App 内页面同源。**只做只读操作**
> （仅调用列表/详情/评论的 GET 接口，不点赞、不收藏、不发帖）。

---

## 快速开始

### 全站抓取（把论坛帖子抓下来做看板）

双击 `wpy-sitewide/一键抓取.bat`，首次会让你输一次学号密码
（之后自动记住，不用再输），然后选：

```
[1] 全部爬取    把全站帖子抓到底
[2] 继续爬取    接着上次没抓完的地方继续
[3] 部分爬取    指定分区 / 日期 / 条数，只抓这些
[4] 补充爬取    只抓上次之后的新帖
[5] 打开看板    启动本地服务后用浏览器打开（推荐，唯一正确方式）
[6] 账号设置    查看账号 / 清除已保存的密码
```

**看板必须用 [5] 打开**，不要双击 `全站看板.html`，也不要用浏览器打开
`全站帖子_raw.json`（约 168MB）或 CSV——大文件会把 Chrome 内存吃爆。
详见 `wpy-sitewide/使用说明.txt`。

## 全站工具能做什么

### 抓取内容

| 内容 | 说明 |
|---|---|
| 帖子 | 标题、正文、时间、作者、等级、头像、分区、标签、点赞/收藏/评论/浏览数、图片链接 |
| 评论 | 全部楼层，含楼中楼（用「父楼ID」表示回复关系）、评论图片、点赞数、是否楼主 |
| 官方回复 | 校务专区帖子的官方答复 |
| 精华 | 推荐位帖子的集合（单独记录，可与分区叠加筛选） |
| 我的帖子 / 我的收藏 | 单独抓取并标记 |

### 看板筛选

- **快捷筛选**：我的帖子 / 我的收藏 / 精华 / 评论未抓 / 正文未取到
- **分区**：8 个真实分区（校务专区、青年湖底、学习新知、交友恋爱、二次元、摆摊、Bugs反馈、美食专区）
- **日期**：某一天，或起止区间
- **热度**：点赞 / 收藏 / 评论 的数值下限
- **用户**：详情里点「看 TA 的全部帖子」，按 uid 精确匹配
- **排序**：最新 / 浏览最多 / 点赞最多 / 收藏最多 / 评论最多 / 最早
- 关键字搜索（标题、正文、作者、标签、uid）

### 抓取特性

- **断点续抓**：进度存 SQLite，中断后重跑接着来，不重复抓已完成的
- **访问速率**：默认 10 QPS（实测连续 60 秒 601 次请求零限流）
- **两道保险**：被限流时速率砍半并暂停；连续失败 12 次自动熔断
- **分页漂移检测**：翻页期间有人发新帖会导致跨页重复，检测并记录到 `pagination_events` 表
- **开始前预估**：显示待抓数量、预计请求数与耗时，确认后才开始

## 安全说明

**凭据文件 `凭据.json` 含明文密码。** 这是有意为之的取舍：

- Windows 没有可靠又跨平台的加密方案，做一层假加密只会给人虚假安全感
- 实际保护来自三条：项目 `.gitignore` 已排除、Windows 下用 `icacls`
  收紧 ACL（仅当前用户可读）、文件只存在你自己电脑上
- 想取消保存：菜单选「账号设置 → 清除」，或 `python crawl.py logout`
- 也可完全不用保存，改设环境变量（优先级更高）：
  `set WPY_ACCOUNT=学号` 和 `set WPY_PASSWORD=密码`

**数据合规**：抓取的是公开分区内容与评论，含他人昵称头像，
请勿公开传播或用于其他用途。

## 命令行用法

```bash
cd wpy-sitewide

python crawl.py all                 # 全部爬取
python crawl.py resume              # 继续爬取
python crawl.py update              # 补充爬取（只抓新帖）
python crawl.py partial --types 13 --since-date 2026-09-01
python crawl.py status              # 查看进度
python crawl.py logout / whoami     # 账号管理
python crawl.py diagnose            # 评论接口报错时诊断参数

# 常用参数
--limit 100        本轮最多处理 100 条（各阶段含义一致）
--max-total 5000   库中到 5000 条就停（含已有的）
--qps 5            限速（默认 10）
--types 2,3        只处理指定分区
--ids "#MP123456"  只处理指定帖子（支持 App 分享口令）
--no-confirm       跳过开始前的确认（脚本化用）
```

## 已知限制

- **服务端 `total` 字段不可信**：它声称每个分区只有 20 页，实测青年湖底
  第 1200 页仍有数据、学习新知第 300 页仍有数据（实际页数可能是它的几十倍）。
  抓取逻辑**不使用 total 判断结束**，而是「翻到空页」或「连续 3 页无新帖」为止。
  旧版本曾因此只抓到 20 页就停止，可用 `python crawl.py reopen` 重新排队补抓。
- **置顶帖会造成 id 断层**：`e_tag=top` 的帖子被强行插在首页，挤掉正常帖子的
  位置，导致相邻两页之间偶尔漏掉个别 id。脚本会检测并记录到
  `pagination_events` 表（kind=gap），但不会自动补抓。
- 列表接口返回的正文可能不完整，完整正文需跑「补全正文」阶段。
- 已删除的帖子正文取不到（看板标记为「正文未取到」），其评论也不再尝试。
