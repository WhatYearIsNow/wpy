微北洋「青年湖底」全站抓取 · 使用说明
======================================

【怎么用】

双击「一键抓取.bat」，第一次会让你输一次学号密码（之后不用再输），
然后选一个：

    [1] 全部爬取    把全站帖子抓到底（第一次用这个）
    [2] 继续爬取    接着上次没抓完的地方继续
    [3] 部分爬取    指定板块 / 日期 / Mp号，只抓这些
    [4] 补充爬取    只抓上次之后的新帖子
    [5] 打开看板    启动本地服务并用浏览器打开（唯一正确方式）
    [6] 账号设置    查看当前账号 / 清除已保存的密码
    [7] 重新排队    把「已完成」的板块打开，继续往更旧的帖子抓
    [8] 重建看板    数据更新后重新生成页面

抓完不会自动打开浏览器。请用菜单 [5] 打开看板。中途按 Ctrl+C 可停下，下次运行接着来。

【重要】不要用浏览器直接打开这些文件：
    data\全站看板.html      没有数据接口，打开是空页面
    data\全站帖子_raw.json  约 168MB，Chrome 可能吃掉数 GB 内存甚至卡死
    data\全站帖子.csv       约 64MB，同样不要用浏览器打开


【四种爬取的区别】

[1] 全部爬取
    每个板块从第 1 页抓到最后一页。数据量最大，耗时最长。

[2] 继续爬取
    上次没抓完时用。它接着每个板块已抓到的页码继续，
    已经抓完的板块会自动跳过。

[3] 部分爬取
    分两步问：

      第一步 选分区：[1] 自己选（可多选，如 2,3）  [2] 全部 8 个分区
      第二步 选范围：[1] 按帖子数量（如 100，开发测试用）
                    [2] 按日期（某天或起止区间）
                    [3] 不限（抓到底）

    例：只想抓美食专区最近的
        分区选 13，范围选日期，起始填两周期的那天

    说明：抓取只处理「库中还没抓过正文/评论的帖子」，已抓过的不重复抓，
    所以范围决定的是处理哪些，不会因为反复运行而重复污染数据。

    注意：「精华」不是板块，这里填不了。它是论坛推荐位，
    工具会单独抓取，看板里有「只看精华」筛选器。

[4] 补充爬取
    日常更新用。它自动记住库里最新帖子的编号，
    只抓比它更新的新帖，然后补这些新帖的正文和评论。


【跑的时候看什么】

屏幕上会持续显示三档进度，不用猜跑到哪了：

    总进度 [████████░░░░░░░░░░░░░░░░]  33.3%  第 3/6 步
    本步：补全正文与图片
    补正文 [██████████████░░░░░░░░░░░░░░]  50.0% 20/40，已用 0 分 6 秒，预计还需 0 分 6 秒

  - 最上面是整体 6 步的进度条（0~100%）
  - 中间是当前这一步在做什么
  - 下面带进度的行是这个板块/这批任务的完成度，含预计剩余时间

窗口顶部也有汇总：
    已抓 406 帖（正文 406）｜评论 397 帖 / 8120 楼｜板块 6/8 完成


【访问速度】

默认 10 QPS（每秒 10 个请求）。这是实测出来的：
以 10 QPS 连续请求 60 秒共 601 次，全部成功、零限流、延迟稳定无劣化。

两道保险（即使触发风控也会优雅退让，不会把账号打废）：
  - 服务端返回「请求过多」时，自动把速率砍半并暂停 30 秒
  - 连续失败 12 次就熔断停止

想调速用命令行，菜单里不暴露这些参数：

    python crawl.py all --qps 5        # 保守
    python crawl.py all --qps 20       # 激进（不建议）

两个容易混淆的条数参数：

    --limit 100        本轮最多处理 100 条（各阶段含义一致，不含已有的）
    --max-total 5000   库中帖子到 5000 条就停（把已有的也算进去）

想「先抓 100 条看看」用 --limit；想「总量控制在 5000 条」用 --max-total。

注意：所有线程共用这一个速率上限，调大并发不会突破它。


【登录：只需输一次】

第一次运行会让你输学号和密码（密码输入时不显示）。输完会保存到
本目录的 凭据.json，之后运行就不用再输了。

这个文件的安全性：

    - 只存在你自己电脑上，不上传、不发到网络
    - 已被项目 .gitignore 排除，不会被提交到代码仓库
    - Windows 下会自动用 icacls 收紧权限，只有你的账号能读
    - 内容是**明文**（Windows 没有可靠又跨平台的加密，做一层假的加密
      只会给人虚假安全感），真正的保护是上面三条

想换账号或取消保存：菜单选 [7] 账号设置 → 清除已保存的密码，
或直接删掉 凭据.json。

不想保存也行：设环境变量再用（环境变量优先级更高）：

    set WPY_ACCOUNT=你的学号
    set WPY_PASSWORD=你的密码


【抓了什么，存在哪】

    帖子      标题、正文、发布时间、作者、等级、头像、板块、标签、
              点赞/收藏/评论/浏览数、图片链接
    评论      全部楼层，含楼中楼（用「父楼ID」表示回复关系）、
              评论图片、点赞数、是否楼主
    官方回复  校务专区帖子的官方答复
    精华      推荐位帖子的集合（单独记录，可与板块叠加筛选）
    我的帖子  你自己发的帖子（单独标记）
    我的收藏  你收藏的帖子（单独标记）

    以上文件都在 data/ 子目录里（代码与数据分开，升级脚本不会误删数据）

    全站看板.html          直接双击用浏览器打开，无需联网
    全站帖子.csv           Excel 可打开
    全站帖子_raw.json      原始数据
    sitewide.db            全部数据 + 进度
    运行状态.txt           随时可看「现在到底在不在跑」
    抓取日志.txt           运行记录


【看板怎么看】

    勾选框：我的帖子 / 我的收藏 / 精华 / 评论未抓 / 正文未取到（可叠加）
    日期：  选起始、结束日期，只留这个区间发布的（只填一端也行）
    热度：  填点赞≥、收藏≥、评论≥ 的数值，只要够热的
    搜框：  可搜标题/正文/作者/标签，也能搜 uid
    排序：  最新发布 / 浏览最多 / 点赞最多 / 收藏最多 / 评论最多 / 最早发布
    清除筛选：一键恢复全部

    详情里会显示「作者 uid」和「看 TA 的全部帖子」按钮，
    点一下就能筛出该用户的全部帖子（按 uid 精确匹配，不会因重名误伤）。

    点任意卡片打开详情，能看到完整正文和全部评论。
    如果某帖评论还没抓，详情里会写明「这一帖的评论还没抓取（原帖有 N 条）」，
    而不是假装没有评论。


【常见问题】

Q: 抓不到评论，报 code=400？
A: 运行 python crawl.py diagnose 诊断参数。
   脚本遇到这类错误会立刻停下并保留帖子为"未抓"，修好后重跑即可。

Q: 提示熔断停止？
A: 连续多次失败（网络断/服务端异常）触发的保护。检查网络后重跑。

Q: 「分管部门」很多是空的？
A: 正常，只有校务专区（板块ID=1）的帖子有这个字段。

Q: 想抓很多但怕太久？
A: 用 [3] 部分爬取，填个条数上限，先看看效果。


【命令行用法】（等同菜单）

凭据走环境变量：

    set WPY_ACCOUNT=学号
    set WPY_PASSWORD=密码

    python crawl.py all        # 全部爬取
    python crawl.py resume     # 继续爬取
    python crawl.py partial --types 2 --since-date 2026-09-01
    python crawl.py update     # 补充爬取
    python crawl.py status     # 看进度

    python crawl.py all --limit 100          # 只抓 100 条
    python crawl.py all --concurrency 4      # 并发数调大
    python crawl.py partial --ids "#MP123456"


【导出帖子为图片】

在看板里点开任意帖子，右上角有「导出图片」按钮，
会把这条帖子存成 PNG（含作者、时间、标题、正文、图片、计数）。

请始终通过菜单 [5]（本地服务）打开看板：
  - 列表和详情默认显示缩略图（thumb，约为原图 1/18 体积）
  - 点击图片放大、导出 PNG 时自动换成原图（origin）
  - 评论很多的帖子会先显示前 150 楼，点「加载更多评论」再展开；
    导出含评论的图片时会自动把剩余楼层拉齐

原因：浏览器允许页面「显示」跨域图片，但禁止脚本「读取」它的像素
（防止隐私泄露）。导出需要读像素，所以 file:// 下做不到；
从本地服务打开后页面与图片同源，就没有这个限制。

图片按需下载并缓存到 data/img/thumb/ 与 data/img/origin/，
第二次打开就不用再下。用完回到命令行窗口按 Ctrl+C 停止服务。

想提前把图片全部下载好（用于离线查看）：python crawl.py image
