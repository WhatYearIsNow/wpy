# 个人互动邮件提醒

只为显式配置的本人微北洋账号发送邮件，不增加看板通知入口。默认每 300 秒检查一次，
适用于服务常驻、浏览器关闭后仍需提醒的情形。运行时仅使用 Python 标准库。

## 上游实现依据

本次核对 `twtstudio/WePeiYang-Flutter` 的 `flutter3.44` 分支，版本 `908ab7d`。
官方客户端通过湖底 token 请求消息列表，并通过个推和原生厂商通道提供手机推送；
本次检查的消息链路未发现 SMTP 邮件转发或面向第三方的消息订阅接口。

- [消息接口](https://github.com/twtstudio/WePeiYang-Flutter/blob/908ab7d/lib/message/network/message_service.dart)：
  `GET message/likes` 是点赞，`GET message/floors` 同时包含帖子评论与评论回复。
- [消息类型与页面](https://github.com/twtstudio/WePeiYang-Flutter/blob/908ab7d/lib/message/feedback_message_page.dart)：
  两个列表均用 `type=0/1` 区分帖子/评论目标；`message/replys` 是校务回复，不在首期范围。
- [设备推送绑定](https://github.com/twtstudio/WePeiYang-Flutter/blob/908ab7d/lib/home/view/home_page.dart)：
  官方 CID 绑定属于原生推送链路，本功能不向该接口注册独立设备。

上游源码内嵌的[社区规范附则](https://github.com/twtstudio/WePeiYang-Flutter/blob/908ab7d/lib/auth/view/privacy/lake_privacy_dialog.dart#L252)
限制未经许可的非官方客户端和脚本访问。降低频率不等于获得平台许可，实际运行应遵守官方规则。

## 简略实现方法

1. 使用显式环境配置登录本人账号，论坛 token 只留在进程内存。401 时最多续登一次；
   持续认证失败或 403 退出，不回退到看板或抓取账号会话。
2. 串行分页获取消息，每页 20 条、请求间隔一秒。首次评论检查只记录最新一页，随后按
   已见的最大评论 ID 增量读取，到达旧 ID 即停止，避免每五分钟重扫多年历史。
   点赞是聚合计数，旧目标可能继续增加，因此仍完整读取点赞列表。
   默认每类最多 50 页、每次响应最多 2 MiB。评论排序变化、分页失败、重复、交叠或达到
   上限时，不提交本轮基线或推进游标。
3. 第一次检查仅建立基线，不追发历史。以后按评论 ID 去重，按点赞聚合计数的上升识别变化。
   读取官方消息不会调用已读接口；官方未读数不作为唯一变化依据。
   只为需要发信的新互动补读缺失的帖子/原评论上下文，同帖和同评论在一轮内只补读一次。
   网络失败不提交基线；内容已经删除时保留提醒并明确标注不可访问。
4. 新增互动与待发邮件在独立 SQLite 的同一事务落盘，同一轮五分钟内发现的所有新增互动
   合并为一封，不按互动条数拆信。正文逐条列出，主题概括本轮涉及的类型。
   SMTP 失败按五分钟至一小时退避补发；发送记录保留 30 天，去重记录继续保留。
5. 默认在一轮完成后等待五分钟。网络故障逐步退避；限流至少等十五分钟，若 HTTP
   `Retry-After` 更长则遵从该等待时间。每个状态目录只允许一个任务运行。

可选配置大肥鱼状态数据库后，每轮只读其中登记的自有帖子/评论 ID。对这些内容的点赞、
帖子评论和评论回复仍写入本通知服务的去重基线，但不生成「微北洋」邮件，避免与大肥鱼动作邮件
重复；其他人工内容的通知不受影响。状态数据库不可读时不推进本轮消息基线，不静默退化为重复发信。

消息基线和收件人绑定同一私有状态目录。更换账号或收件人时需使用新目录，以免把旧队列
投递给另一人。账号和收件地址仅用于带本地随机密钥的 HMAC，不明文写入状态身份。
通知正文属于私有运行数据，不进入 Git、公开导出或共享帖子数据库。

## 配置和命令

复制 `deploy/env.notify.example` 为本机忽略的 `deploy/env.notify`，通过 shell 或 systemd
加载；Python 不会自行读取环境文件。`WPY_ACCOUNT` / `WPY_PASSWORD` 必须显式提供，
不自动读取历史凭据文件。API 应用密钥使用现有 `WPY_APP_KEY` / `WPY_APP_SECRET`。

`WPY_SMTP_CONFIG` 指向私有 JSON，兼容 course 的 SMTP 配置：

```json
{"user": "", "pass": "", "to": "", "host": "smtp.qq.com", "port": 465}
```

`pass` 为 SMTP 授权码，`to` 为空时发给发件账号自身。当前使用校验证书的隐式 TLS，
默认 QQ SMTP 465。配置文件不得提交，建议权限为 0600。若复用已有配置，运行账号必须
具有读取权限，无需修改 course 业务代码或启动其服务。

可选 `WPY_NOTIFY_BASE_URL` 为看板根地址。配置后邮件提供帖子级 `?postId=` 链接，
跳转依赖目标站已有的热榜深链接支持；目前不承诺定位到某条评论。未配置则只列帖子信息。

可选 `WPY_NOTIFY_AI_STATE` 指向大肥鱼状态目录或其中的 `agent.sqlite3`。通知进程只读取
`own_content` 的帖子/评论 ID，不读取账号、动作正文或邮件队列；运行账号必须对该数据库及 WAL
所在目录具有只读访问能力。

```bash
python -m wpy notify --help
python -m wpy notify --test-email   # 一封真实合成测试邮件，不登录论坛、不建立基线
python -m wpy notify                # 单次检查；首次只建立基线
python -m wpy notify --watch        # 默认五分钟间隔，SIGTERM/Ctrl-C 后退出
python -m wpy notify --retry-mail   # 只补发已到重试时间的邮件，不访问论坛
```

测试邮件采用 course 的无固定主题前缀、正文标题、键值表和备注样式，提供纯文本与 HTML
两种正文。所有论坛文字均转义，不加载外部图片；测试内容明确标记为合成互动。
日志只包含数量和通用错误，不打印账号、token、收件地址或原始远端响应。

每条互动使用相同字段顺序：通知类型、`#MP` 帖号、帖子标题、帖子正文、帖子点赞数。
评论获赞或被回复时再列出「我的评论」和评论点赞数；回复类消息列出回复人、时间和详情。
发件人显示名为「微北洋」。主题直接显示「有人点赞了你的帖子/评论」或
「有人回复了你的帖子/评论」，多类型合并时列出相应类型，不添加项目名前缀、帖号或标题。
测试主题追加「（测试）」以免混淆。帖子正文最多保留 8000 字符，评论/回复最多
4000 字符，超过时明确标注「已节选」；正文暂不可用、纯图片或已删除均明确标记。

## 独立运行

`deploy/wpy-notify.service` 提供独立服务模板，不改变看板、抓取服务或浏览器登录期限。
模板默认工作目录为已有部署路径；安装前需先同步或安装包含本功能的代码，并准备
`deploy/env.notify` 和可由 `wpy` 账号读取的 SMTP 配置。

服务使用 `/var/lib/wpy-notify` 保存隔离的运行目录和通知状态，目录权限 0700、文件 0600。
退出码 2 表示认证失败，systemd 不自动重启；修复配置后由维护者重新启动。
模板自身不启用服务，也不会自动复制凭据或修改已有部署。

## 限制与验证

- 点赞列表是聚合状态，没有每个点赞事件的唯一 ID、点赞人或准确时间。
  计数先减再增且发生在两次检查之间时可能无法察觉；首次出现的点赞目标仅展示累计数，
  标记新增数量未知，不会将累计赞数当作新增赞数。
- 如果上游在官方客户端读消息后不再提供某些记录，且读取发生在两次检查之间，
  轮询可能漏掉这类短暂记录，不能保证覆盖每个事件。
- 评论增量读取依赖接口按评论 ID 降序返回；每页和页间顺序都会校验，异常时暂停本轮。
  延迟公开、编号早于游标的旧评论可能无法捕获，不保证补发启用前历史。
- SMTP 接受发送不等于收件箱已收到。若服务器已接受但本地成功状态落盘前断电，
  补发可能重复；重试使用同一 Message-ID，但不承诺严格一次投递。
- 每轮完整检查两个列表。没有历史分页时通常为两个请求；页数增加时请求量也会增加。
  新互动缺少正文或原评论详情时另有按需补读请求。
  可调 `--max-pages`（1–200），达到上限会明确失败，不静默忽略旧页。
- 邮箱不可用时仍可记录新事件；论坛不可用时先尝试补发队列，支持单独补发命令。

离线验证：`python -m pytest tests/test_notifications.py`。测试覆盖四种互动、首次基线、
重启去重、队列失败补发、事务回滚、分页完整性、身份隔离、认证续期、限流退避、
重复任务锁、HTML 转义和 SMTP 请求构造。真实测试邮件只在用户明确授权后发送，
